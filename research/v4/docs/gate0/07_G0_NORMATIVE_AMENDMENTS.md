# V4 Gate 0 — Normative design amendments (candidate for bounded Solmax recheck)

**Status:** G0-RECHECK-CANDIDATE / NOT G0 CLOSED. Dated 2026-11-12. This is design, not executable V4 code, not evidence that a brokerage connection works, and not authorization for an order. The six amendments below are **normative** and supersede any inconsistent sentence retained in the original draft or context documents. The revised research protocol and engineering contract explicitly incorporate and cross-reference these rules.

## A1 / BLOCKER — Stable outcome identity; prospective scoring population

**Four different IDs, never conflated:**

1. `outcome_event_id` is a stable, canonical hash of the underlying reference entity/series, **measurement period**, measurement variable and pre-existing release/event-instance identity. Neither venue, contract/conid, market-family display text, threshold, release-clock time, trade-stop, rule revision, nor first-observation time changes it. A delayed/relisted event keeps the same ID. Cross-venue synonyms and renamed releases require a versioned alias map verified by source evidence; ambiguous identities => `HOLD_IDENTITY` and no training/evaluation or actionable recommendation. IDs do not use final realized values.
2. `contract_target_id` identifies a **specific** payout proposition: venue/product and binding rule version, measurement function, comparator, strike, rounding, unit, exceptional settlement provisions. A substantive rule alteration creates a new target linked to the same `outcome_event_id`; conid/relisting maps to a target via an audited one-to-many history, not unordered overwrite. For a valid complementary YES/NO pair, store one canonical YES target plus two side instrument IDs. Contradictory or duplicate conids => `HOLD_PAIR_CONFLICT`, order-independent.
3. `dependence_block_id` groups outcomes with shared release mechanisms, announcement calendars or overlapping measurement windows. It may unite several outcome event IDs across families and venues. A connected component of known dependencies is the minimum split/uncertainty unit; ambiguous overlap is held or merged conservatively. Both sides and all thresholds of one outcome always remain in the same block. A prospectively selected primary family assignment avoids counting an identical outcome in multiple families.
4. `concentration_group_id` is the coarsest defensible economic exposure group across linked targets, alias releases and related outcomes; risk caps aggregate **all** pending intents, live orders and positions across it. Changes or alias discovery cannot reset the cap. Until identity is reconciled, no actionable order.

**Freeze before prospective labels:** the primary unit is one `outcome_event_id` at one predefined **as-of** *input* evaluation anchor `T_g`. Before prospective outcomes also register per-family **issuance deadline** `D_g` and record each model's actual issuance `I_{M0}`, `I_{M2}` or `I_fallback`. `D_g` may follow `T_g` only when the G1 rule explicitly allows it; any such forecast still uses only evidence received+ingest-ready by `T_g`, is issued by `D_g`, and must pass the source-state guard at actual issuance. A state becoming known before issuance excludes that target rather than introducing hindsight into a forecast. G1 may select the supported family roster, release-relative anchor and numeric offset, admissible bid/ask synchronization window and dependence-block granularity using **outcome-blind capability/coverage evidence** only. Lock these, enrollment start, finite target horizon and data finality deadline before scoring. Deterministically choose the last complete admissible snapshot **at or before** `T_g`; never substitute a later quote for a missing cutoff snapshot. Issue M0 and M2 (or a declared fallback) from the same input cutoff with pinned model/update-policy versions, **by the registered `D_g`**, with their actual issuance timestamps stored. A fallback is valid only when genuinely issued by `D_g`, never synthesized after labels. One canonical YES probability per verified complementary pair, not two observations from NO.

Eligible threshold set `J_g` is defined by contract/rule status and quote/feature evidence **available by `T_g`** and not by final outcome, owner trades, budget, eventual edge or realized return. At the cutoff, resolve venue/product aliases using a **G1-locked primary target selection precedence** per canonical outcome and threshold. If more than one inconsistent payoff target remains, exclude that strike as `HOLD_TARGET_CONFLICT`; never count both or choose by future data. Within group use equal weights across distinct **paired and label-matured** thresholds `J_g^pair`, a subset of all enrolled `J_g^enrolled`. Define `d_g = (1/|J_g^pair|) sum_{j in J_g^pair} ((p0_gj-y_gj)^2 -(p2_gj-y_gj)^2)` only if this denominator is positive. Missing counterpart/late/void thresholds remain in the **enrollment coverage** denominator, not the score denominator. A threshold difference +.12 paired with one missing M2 therefore yields event score +.12, not +.06; no paired threshold means an unavailable event score. Never impute a missing prediction as zero improvement; only a genuine on-time M0-shrinkage fallback contributes a zero. First average `d_g` equally across outcome events assigned to each locked family, then equally across predeclared eligible families (an exact fixed family-weight vector may be registered at G1 using capability evidence). If a family has no eligible common-support event by the predeclared cutoff, report the absence and do **not** renormalize weights opportunistically; whether the primary effect is undefined or the family is omitted must be registered at G1. Uncertainty resamples `dependence_block_id` (not rows or threshold contracts), stratified by family where feasible. Report effective independent block count.

**Common support:** require quality-qualified M0 and an **on-time issued** M2 or preregistered M2-to-M0 shrinkage fallback. If the fallback is actually issued by `D_g` using `T_g` inputs and with legal source state at issuance, `d_gj=0`; don't create a fallback retrospectively. No M0 => `MISSING_M0`; no issued M2/fallback => `MISSING_M2`; void/exceptional resolution => nonbinary/`VOID`; final label after prespecified maturity deadline => `LATE_LABEL`; no legal quote => `NO_CUTOFF_SNAPSHOT`. These reasons remain in an enrolled-inventory coverage denominator and separate missingness table; no post-outcome backfilling. The primary effect refers **only to the prospectively defined common-support cohort**, not all discovered markets. Trading/execution readiness is **not** an inclusion criterion for predictive skill. Unknown account fee, denied trade permission, insufficient budget, unknown executable fee upper bound and reservation failure produce **trade-only** HOLD/NO_TRADE; where the M0/M2 forecast is otherwise legal and on-time, it remains in the paired skill cohort and is scored when the binary label matures.

**Identity test:** duplicate polls and YES/NO views, reschedule, relist, revise rules, rename markets, reverse duplicate rows; outcome ID, dependence block, split and exposure group persist. The target version changes only for a substantive payoff change. Test 100 thresholds vs 1 threshold and a cross-family correlated release: one outcome weight each, and block-level uncertainty.

## A2 / BLOCKER — As-of source-state legality and finalized labels

At every candidate time `T` use **only source evidence already received and ingested by `T`**; record source-vintage time, reported issue/publication time, local receipt and ingest-ready time, evidence content hash and source authority. Event-valid or displayed publication time alone never proves availability. Rule source and revision version are pinned. For every `contract_target_id` evaluate exact comparator (`>`, `>=`, etc.), strike, rounding, unit and exceptional clauses.

`state_asof(T)` is one of: `INSUFFICIENT_OR_CONFLICTING`, `OPEN_UNDETERMINED`, `PARTIAL_BOUND_YES_IMPOSSIBLE`, `PARTIAL_BOUND_NO_IMPOSSIBLE`, `KNOWN_YES`, `KNOWN_NO`, `VENUE_UNDER_REVIEW`, `VENUE_FINAL_BINARY`, `VOID_OR_EXCEPTIONAL`. A verified **monotone/irreversible** partial bound may determine an outcome without a final release; a revision-prone observation is `INSUFFICIENT_OR_CONFLICTING` or `OPEN_UNDETERMINED` with provisional flags until irreversibility is justified. Predetermined targets are withheld from the *primary predictive cohort* and any actionable suggestion; qualifying partial bounds on still-open propositions constrain distribution support, not retroactively alter older forecasts. Unknown rule/source => HOLD. Never infer finality from a schedule, UI expiration, or a stale quote.

Distinguish **primary scoring** from later **training**: an authoritative venue-binding binary result (or binding source vintage under verified venue rules) must be effective, observed and ingest-ready by the registered **scoring-only** deadline `S_g` to join `J_pair`; otherwise disposition `LATE_LABEL`, retained in enrollment/coverage but permanently excluded from the fixed primary scoring cohort. For training at scheduled checkpoint `U`, that same binding result must instead be effective, observed and ingest-ready **<= `U`**; `S_g` does not constrain subsequent training, which separately enforces exact target/rule, input/issuance, protected distinct dependence blocks, embargo and update-policy schedule. No later-arrived 12:00 result may enter a 12:05 fit if first received 12:08; a later 12:10 fit may consider it even if it missed `S_g=12:06`. Track separate official venue binding, source release, ingest, trade-stop, payout and broker cash-posting times. An upstream data revision *after* venue binding does not silently relabel the venue-final target. Exchange correction => append correction with lineage and versioned restated scores, never overwrite prior forecast or prior fit evidence. `VOID_OR_EXCEPTIONAL` goes to a separate payoff workflow, not binary Brier/training without an explicitly defined estimand. Distinguish predictive outcome from cash settlement.

**State tests:** irreversible partial source exceeds a strict threshold while market open; equality under `>` vs `>=`; review and revision-prone cross; out-of-order clock/receipt; S04: 12:00 final first received+ready 12:08 with `S_g=12:06` permanently `LATE_LABEL` for primary scoring, rejected for update at `U=12:05`, admissible at `U=12:10` only with the other training guards; revised upstream after binding leaves original binding unchanged unless venue corrects it.

## A3 / MATERIAL — One M0, defensible per-trade support, cash accounting

For a verified ordinary complementary $0/$1 payoff pair, compute **one** M0 from contemporaneous YES two-sided book as `M0_Y = (bid_Y + ask_Y)/2`, with source/protocol version locked. NO book is a mirror/consistency check; never a second independent observation. G1 must show exact timestamp semantics, side freshness/synchronization, price/size units, venue status, `6509` mode, reconnect gaps and mirrored tolerances. Broker field `6509=real-time` is **not** proof of simultaneous freshness of both legs; locked/crossed/one-sided/missing/delayed books => frozen exclusion reason, not fallback to a convenient side. No M0 from executable ask alone. M0 model baseline is not a mechanically fee-adjusted executable return.

An actionable trade needs a **supported** probability interval `[L_Y,U_Y]` from a preregistered family-specific uncertainty/support/calibration procedure and meaningful sample/feature support; if unavailable => `NO_TRADE_UNSUPPORTED` even when point-forecast M2 exists. YES lower bound is `L_Y`; NO lower bound is `1-U_Y` (not `1-L_Y`). A group-level Brier confidence interval is **not** a per-contract confidence interval. For verified binary $1 payout, conservatively compare `p_side_lower * $1 - **manual_intent.limit_price_ceiling** - upper_bound_fees - execution_reserve` using the **strict `>` comparison** with the preregistered positive margin **at the maximum limit that the human may submit** (equality is `NO_TRADE_EDGE_AT_LIMIT`); verify current executable ask as a separate freshness/marketability check. The exact ceiling screened must equal the ceiling embedded in the durable manual intent and max-cost reservation. A lower ask cannot rescue a failing allowed ceiling. E.g. `L=.60`, ask `.40`, permitted limit `.58`, fee `.01`, reserve `.02`, positive margin `.05`: ask edge `.17`, authorized-ceiling edge `−.01`; reject `NO_TRADE_EDGE_AT_LIMIT` despite all-in `.59 <= 1.00`; unknown quote, payout or fee upper bound => HOLD. Freeze exact estimator, minimum support, fee and margin values at appropriate gates **before first G3 order**; G0 does not invent numbers.

Actual economic reporting is restricted to **matched, matured manual fills** under the declared frozen decision policy: `(sum matched net cash PnL)/(sum their actual all-in paid outlay)` (undefined for zero matched spend); include dollar PnL, denominator, maturity cutoff and counts/amounts unsettled. Report separately all observations, decisions, manual attempts, refusals, cancellations, partial fills and unmatched broker activity. Unmatched/uncertain cash remains pending, not PnL. A cash-flow ledger includes premium purchases for every acquired leg, fee adjustments/coupons/refunds, one broker-recognized netting credit if opposite ForecastEx positions offset, and any venue exceptional payout. Do not count a $1 offset credit twice or infer offset from displayed prices. Reconcile quantity and cash to broker ledger.

**Quote/cash tests:** YES .41/.45 and NO .55/.59 => one M0 .43. YES interval [.52,.68] => NO lower .32; NO all-in cost .40 => nonpositive conservative margin. Offset premiums .40+.35+fees .02, one credit 1.00 => net .23 before coupons. Cancel unfilled => zero fill, no synthetic PnL; unmatched fill, partials, nonbinary payout or late fee adjustment stay distinct.

## A4 / BLOCKER — Locked adaptive policy vs M0, separate champion promotion

**Primary scientific comparison is not the best nightly challenger.** Freeze one `update_policy_id` defining family architecture, feature availability, label-admission rule, training/regularization, calibration, fallback and *scheduled daily fitting* before prospective cohort. On each forecast as-of cutoff, model release/checkpoint and data cutoff are pinned before producing M0/M2. Evaluate the **issued predictions** of this *adaptive policy* paired with M0 on one predefined anchor per outcome. Earlier finalized independent events may enter later scheduled updates only if policy authorizes that timing, even if they have already been scored, provided their labels were genuinely observed+ingest-ready by the later update and they are distinct from the later target's protected dependence block; same outcome and its correlated protected block may never leak across a forecast's training boundary. Training, tuning, calibration and score groups are **temporally disjoint at each forecast** across its as-of and embargo boundary, not permanently disjoint for the life of the adaptive policy. A previously scored outcome block that later becomes venue-binding+observed+ingest-ready may be ingested at a **later scheduled** update to forecast a different eligible block, if permitted by `update_policy_id` and its embargo. That does not alter its earlier issued score or permit same-/overlapping-block leakage; change the policy in response to observed scored results => new policy ID and **new prospective primary cohort**.

**Cadence boundary:** permitted intraday shadow refits produce versioned descriptive outputs only; they cannot silently change the preregistered *primary daily* update policy, schedule, candidate-selection rule, forecast stream or the primary claim. A score-motivated change creates a new policy ID and future cohort.

**Formal look design:** G1 must register prospectively a finite enrollment window plus a single formal terminal test after the window/maturity cutoff, a fixed family weighting and dependence-block bootstrap/confidence/test rule with no interim formal p-value views. Daily Brier/calibration/PnL dashboards remain explicitly *descriptive*; any design revision motivated by those dashboards starts a new forward cohort. Repeated formal tests across families or released policies require a predeclared multiplicity plan; otherwise no inferential positive claim. Feasibility diagnostics at 30/100 independent groups are not promotion evidence by themselves. No fixed numeric power promise absent G1 feasibility assessment.

**Separate production promotion:** a candidate release is locked (including calibration and feature schema) **before** a fresh protected event-block cohort; its paired comparator, sample rule, single look date/maturity and decision thresholds are recorded in `promotion_plan_id`. For a fixed-release promotion test, both candidate and comparator are forbidden from fitting/tuning/calibrating on protected labels at any stage of that test. Alternatively compare two fully specified updating policies with earlier-group label updating permitted on a frozen schedule, reporting that estimand explicitly. Do not choose among versions after viewing the same cohort's score differences; an additional test or look needs a new forward cohort or registered sequential/multiplicity design. Distinct signed audit records authorize (i) candidate training checkpoint and (ii) champion promotion. Training success never implicitly promotes.

**Promotion tests:** reject future/late/same-event label, calibration containing protected groups, challenger selected post-hoc on comparison block, and extra formal look. Permit daily challenger training on legal mature labels even if no production promotion. The first G4 checkpoint may be independently reviewed after **venue-binding observed+ready binary labels** and a lawful training checkpoint **with zero manual orders or fills**; it validates label admission, snapshot/time lineage and model update. Fill/cash reconciliation is a separate G4 subreview when actual trades exist; zero fills must not hold the label/update gate hostage.

## A5 / BLOCKER — Durable manual order-intent reservation and broker reconciliation

Before showing an **actionable** suggestion, in one durable SQLite transaction: validate event/contract identity, quote/source/hand-off freshness, all risk budgets and broker reconciliation status, allocate a unique one-use `manual_intent_id`, write snapshot+forecast+decision+reserved **worst-case all-in cash exposure**, and commit. The UI must display no executable candidate before commit acknowledgement. **No programmatic order submission.** Include target side, conid, count, limit ceiling, maximal fees and non-price costs, quote/source evidence, model+policy IDs, creation and expiration. Expiration of the displayed suggestion does **not** imply that an order was never submitted.

All `RESERVED`, `SUBMISSION_UNKNOWN`, `SUBMITTED`, `CANCEL_REQUESTED`, `PARTIAL_FILLED`, `OPEN_UNRECONCILED` and filled/unsettled balances remain risk-occupied across process death, midnight, app session changes and broker UI switching. `CANCEL_REQUESTED` does not release funds. Release or replace reservations **only** upon trusted broker/manual reconciliation evidence that no live order or exposure remains, accounting for filled and remaining quantity. An unknown activity / disconnected session => risk `HOLD_RECONCILIATION`. Budget spent today and total concurrent exposure are independent; past open obligations remain in the concurrent constraint. Match broker activity across all user-managed accounts/usernames in declared scope or fail closed. Reserve one economic concentration group across aliases, relistings and thresholds. No duplicate intent on retry: idempotency key + DB uniqueness. A manually placed unmatched trade triggers HOLD until reconciled.

SQLite uses `journal_mode=WAL` and `synchronous=FULL` **on a verified supported durable local volume**; verify actual settings and transactional capacity in G2. Write content-addressed private snapshot/evidence bytes durably **before** committing their references in DB; fsync object file, atomic rename + directory sync as supported, then transaction commit. Ensure backup is consistent across DB/WAL, evidence objects, manifests and keys; restore-and-replay must recreate outstanding intents and hashes. No deletion of data because it is older than local trading day. If session handoff breaks quote timing, go `NO_TRADE` until a new valid, independently captured state.

**Crash tests:** crash after display or submission before broker import; second suggestion cannot over-allocate; concurrent $0.60 reservations under $1 group cap (one accepted, one rejected); cancel-requested vs cancel-confirmed; cancel/partial-fill race; suggestion expires but order pending; rollover; broker disconnection; restored archive plus DB; foreign/unmatched manual trade.

## A6 / MATERIAL — Itemized skips and permission-aware reproducible export

Use `scan_item_disposition` for **every discovered item**, even where no quote or forecast exists. Types include `DISCOVERED`, `NO_RULE`, `AMBIGUOUS_PAIR`, `UNKNOWN_SOURCE`, `MISSING_QUOTE`, `DELAYED_OR_STALE`, `OUTCOME_ALREADY_DETERMINED`, `MODEL_UNSUPPORTED`, `ELIGIBLE_NO_TRADE`, `SUGGESTION_RESERVED`, `API_ERROR`, `NOT_COVERED`, `OUTAGE`. Preserve `scan_id`, item/alias/contract refs when available, source/evidence refs, rule version, reason code(s), decision time and reason version; `forecast_id` is mandatory for **issued paired/scored** dispositions and whenever a decision uses issued model predictions; it is absent for preforecast `NO_RULE`/no-quote holds and for baseline-only states without an actually issued M2/fallback. Observed M0-only emission may reference its **M0 issuance ID** without inventing a paired `forecast_id`. A `record_scope`+typed `scope_ref` is mandatory for every record: `scan` (scan_id), `scan_item` (scan_id+item_ref), `event` (confirmed event ID), `model` (model/update ID, possibly multiple events), `global_health` (health/incident ID). Null `outcome_event_id` is legal for unresolved items, successful scans, multi-event checkpoints and outages. Conditional body requirements must match disposition: `NO_RULE` requires item, reason and error/evidence ref, **not** target/rule/quote/fee/edge/forecast; scored `ELIGIBLE_NO_TRADE` requires actual `forecast_id`. Do not hide API pagination/truncation/gaps behind `zero markets` or summary counts. Global health/outage records may have **no** event key.

Operational private archive is the authoritative temporal replay source. Public exports are generated through a **default-deny typed field whitelist**, per record type and source/channel, recursively validating nested keys and values, arrays, arbitrary strings, high-risk identifiers, metadata and derived/reconstructable quote fields. No generic metadata pass-through and no arbitrary top-level scalar. Redact/halt on a synthetic private marker at any depth. Maintain provenance+permissions catalog (source terms, collected channel, whether raw quote, derived M0/probabilities/features/labels may be retained and/or redistributed). Absence of permission => private-only field or no collection, as appropriate. A public export that permits published paired predictions/labels supports **score replay only**; a full feature and timestamp replay requires authorized, **backed-up** private evidence. Hashes without objects do not establish full reproducibility. Public `research/v4/records/` contains only human-reviewed permissible exports; never auto-push. A Git commit contains no secrets/account IDs/order IDs/IPs/tokens/cookies or unlicensed reconstructed market data.

**Export tests:** no-forecast unknown-rule hold; missing-quote skip; valid `ELIGIBLE_NO_TRADE` tied to a forecast; unknown/duplicate contract key; nested marker and top-level marker; reconstructed quote via derived field denied without a license; private backup/restore reproduces enrolled item dispositions and report counts; public subset can replay only explicitly claimed scores.

## Bounded gate allocations (not assumed results)

**G0 recheck** verifies that A1–A6 were specified consistently and are testable, not that live code works. **Before first G1 request**, independently check V4 read-only entrypoint: precise scheme/host/port/method/path allowlist, TLS trust (V3 default `verify_tls=False` must NOT be inherited blindly), no unsafe redirects, safe sanitized health output; no order endpoint. **G1** verifies complete market inventory, provider terms, conid ambiguity, quote timestamps, negotiated fees and session switching; it selects outcome-blind family roster and freezes operational sampling parameters. **G2** verifies implemented state machine, reserve WAL crash/restore, privacy whitelist, no-order invariant, historical diff and a passing secrets scan on an exact ZIP + Git tree. **G3** alone authorizes bounded manual real orders after actual fee/limit and UI handoff evidence. **G4** validates real final labels and checkpoint lineage; **G5** concerns protected promotion and expansion. Explicit owner constraints: **no paper-trading stage; no automated orders; all-in <= $1 per purchased contract**.
